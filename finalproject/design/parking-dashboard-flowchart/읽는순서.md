# 지하주차장 웹 대시보드 플로우차트

최신 합의 반영: 로그는 발생 시각·이벤트 종류·발생 좌표·위험도(상/중/하)·로봇1 증거 이미지 1장. 이미지 클릭 시 확대, 행 클릭 시 상세 화면에서 처리 상태와 메모 관리.

`parking-dashboard-flowchart.drawio`를 draw.io에 끌어다 놓아 연다. 각 상자·조건·연결선은 편집 가능하다.

| 탭 | 설명 |
| --- | --- |
| 01 전체 플로우차트 | 시작·페이지/빈 데이터 준비, 로그인, 독립 수신, 대시보드, 로그·상세·명령·이력 연결 |
| 02 이벤트 저장 및 로그 반영 | 화재 이벤트와 사진 수신 → 검증 → 파일/DB 저장 → 로그 갱신 |
| 03 로그 조회 및 이미지 확대 | 사진 확대, 상세 조회, 메모와 처리 상태 변경 |
| 04 이벤트 처리 상태 | 신규 → 확인중 → 작업요청 → 조치완료, 권한·상태 검사와 이력 저장 |
| 05 운영 명령 요청 | 웹 요청 → 미션 모듈 수락·진행·완료/실패 결과 표시 |
| 06 순찰·교대 및 이력 | 관측점 방문·순찰·교대 기록과 조건 검색 |

## 발표할 때 설명할 핵심 흐름

“서버와 DB를 준비하고 관리자가 로그인하면 대시보드를 표시합니다. 초기 사건 목록은 비어 있습니다. 로봇1의 화재 이벤트가 들어오면 발생 시각, 사건 좌표, 상·중·하 위험도와 증거 사진 한 장을 저장합니다. 사진은 파일로 저장하고 DB에는 경로를 기록합니다. 서버가 저장된 내용을 조회해 로그 한 행으로 표시합니다. 사용자는 사진을 확대하거나 사건 상세에서 처리 상태와 메모를 관리합니다.”

## 도형 의미

- 타원: 시작, 종료 또는 해당 세부 흐름의 대기 지점.
- 사각형: 처리·저장·화면 표시.
- 마름모: 조건이나 사용자 선택에 따른 분기.
- 메모 도형과 점선: 설명 주석이며 실행 단계가 아님.

전체 탭은 화면 흐름과 데이터 흐름을 함께 보여주는 개요다. 수신 작업은 로그인과 병행하며, 로그아웃해도 서버의 수신·저장은 계속된다. 세부 기능을 마치면 대시보드로 돌아가 사용을 이어간다.

## 데이터와 예외 설계

- 시연용 DB의 사건이 0건이라는 뜻이다. 서버 시작 때 운영 DB를 삭제하지 않는다.
- 로그 좌표는 사건 발생 위치이다. 로봇의 현재 위치로 임의 대체하지 않는다.
- 사진은 동일한 event_id로 연결된 로봇1의 증거 사진이다. 최신 스트림 화면을 임의로 붙이지 않는다.
- 위험도 상/중/하는 수신·판정 결과를 표시한다. 신규/확인중 등 처리 상태와 구분한다.
- 사건당 대표 증거 사진 1장을 표시한다. 해당 사진의 경로를 이벤트와 연결해 보존한다.
- 화재가 발생했다는 이벤트를 웹에서 표시·기록하는 범위를 반영했다. 실제 화재 판정 방법과 등급 기준은 인식 담당과 확정할 계약이다.
- 좌표·등급·사진 일부 누락 시 사건을 먼저 기록하고 누락 항목을 표시하는 것은 예외 처리 제안이다. 보완 메시지는 별도 message_id와 동일 event_id로 연결한다.
- 같은 메시지 재전송은 중복 생성하지 않는다. 같은 사건의 새 보완 메시지는 기존 사건을 갱신하며 처리 상태를 신규로 되돌리지 않는다.
- 사진/DB 저장 실패, 무권한 변경, 동시에 수정된 사건은 오류를 표시하고 성공한 것처럼 처리하지 않는다.
- 이벤트 상태와 변경자·시각·메모 이력은 같은 DB 트랜잭션으로 저장한다. 저장 실패 시 기존 상태를 유지한다.
- 작업요청은 시설 조치 기록이다. 운영 명령 요청과 자동 연결하지 않는다.
- 웹 명령은 요청·기록 역할이고 로봇/미션 모듈이 실제 실행을 판단한다. 응답 지연을 곧바로 실행 실패로 표시하지 않는다.

ROS 토픽은 아직 미확정이므로 샘플 데이터/임시 HTTP로 동일 흐름을 먼저 검증한다. 본 파일은 구현 전 설계이며 실시간 동작 프로그램이 아니다.
