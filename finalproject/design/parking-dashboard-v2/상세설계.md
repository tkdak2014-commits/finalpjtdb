# 지하주차장 웹 대시보드 상세 설계 v2

기준: 사용자가 제공한 2026-09-04 회의 기록, 웹 대시보드 기능 목록 및 참고 화면. Day5_new_v2.pdf는 설계 산출물과 교육 구현 방식의 보조 근거로 사용한다.

상태: 구현 전 임시 설계. 본 폴더는 설계 문서·draw.io·미리보기이며 Flask 운영 코드가 아니다. 종전 `sysmon-day5-flow-concept.drawio`보다 본 설계가 최신 범위를 반영한다.

## 1. 확정 범위와 설계 제안

**사용자 자료에서 확정된 내용**

- Flask + SQLite 기반 관제·기록 시스템. 기능별 모듈 분리.
- 로그인·로그아웃·권한 관리.
- AMR1/AMR2 배터리·위치·연결·순찰/대기/도킹 상태.
- 지도: 순찰 경로, 관측점 7개, 로봇 위치, 이벤트 위치, 안전구역, 도크.
- 로봇/웹캠 실시간 영상, 이상 경고·상세, 증거 이미지·좌표·시각·위험등급.
- 이벤트 처리: 신규 → 확인중 → 작업요청 → 조치완료.
- 운영 명령 요청: 순찰 시작·일시정지·재개·복귀·대피. 웹은 요청 생성·기록·표시를 담당하고 실제 판단·실행은 로봇/미션 모듈이 담당.
- 명령 수락·진행·완료·실패 표시. 사건·명령·순찰·교대 이력 검색.
- 원본 영상은 DB에 저장하지 않고 증거 이미지는 파일, 경로·메타데이터는 DB에 저장.
- ROS 확정 전 샘플 데이터/임시 HTTP API로 개발. ROS 어댑터가 공통 내부 형식으로 변환.

**이번 설계의 제안**

- 관리자/운영자/조회자 3역할, 명령의 `요청됨`·`거절됨` 상태 추가.
- 수신 ID 중복 제거, 상태 버전 검사, 전송 상태와 실행 상태 분리.
- UI 갱신은 초기 버전에서 주기 조회로 시작. 구체적인 주기는 성능 시험 후 확정.
- 참고 이미지를 따라 AMR 2개 + 고정 웹캠 2개, 총 4개 영상 자리를 설계. 실제 소스 개수와 주소는 연동 협의 대상.
- 지도·경로는 초기에는 버전이 있는 JSON 파일로 관리 가능. DB로 옮겨도 같은 API 형식을 유지.

참고 이미지의 녹화·마이크·스크린샷 버튼, 0~100 숫자 위험도, B1/B2 층 구성은 별도 확정 요구사항으로 취급하지 않는다. 목업의 수치·경로 배치는 예시다. 화재는 기존 BR/SR의 제외 범위와 충돌하므로 팀 결정 전 기본 이벤트로 추가하지 않는다.

## 2. 아키텍처와 책임 경계

```text
브라우저 → Flask routes(인증·권한) → services(업무 규칙) → repositories → SQLite
                                         ↕                    ↕
                               공통 연동 어댑터          증거 파일 경로
                               ↙           ↘
                       임시 HTTP / Mock    추후 ROS
                                         ↕
                                감지 / 로봇·미션 모듈
```

웹 요청을 저장했다고 로봇이 수락한 것은 아니다. UI의 `요청됨`은 서버가 요청을 기록했다는 의미이고, `수락됨`부터는 미션 모듈 피드백에 근거한다. 로봇 연결 상태는 마지막 상태 수신 시각으로 판단하며 영상 소스의 연결 상태와 별도로 표시한다.

사용자 로그인 여부와 관계없이 수신·DB 저장은 계속된다. 로그아웃은 사용자 세션만 종료한다. 브라우저 재접속 시 DB에서 이력과 최신 수신 정보를 복원하고 오래된 상태는 수신 시각과 함께 표시한다.

### 파일별 책임 제안

```text
app/
├─ __init__.py                    # Flask 생성, 설정, Blueprint 등록
├─ routes/
│  ├─ auth.py                     # 로그인·로그아웃, 세션
│  ├─ dashboard.py                # HTML 화면
│  ├─ users.py                    # 계정·권한 관리
│  ├─ robots.py                   # 로봇 상태 API
│  ├─ maps.py                     # 지도·경로·관측점·영역 조회
│  ├─ cameras.py                  # 영상 및 소스 상태 조회
│  ├─ events.py                   # 사건 조회·상태 변경·메모
│  ├─ commands.py                 # 운영 명령 요청·진행 조회
│  ├─ history.py                  # 사건·명령·순찰·교대 이력
│  └─ ingest.py                   # 개발용 임시 HTTP 입력
├─ services/
│  ├─ auth_service.py
│  ├─ robot_service.py
│  ├─ event_service.py
│  ├─ command_service.py
│  ├─ patrol_service.py
│  ├─ handover_service.py
│  ├─ map_service.py
│  └─ camera_service.py
├─ repositories/                 # SQL·트랜잭션만 담당
├─ models/                       # 공통 내부 데이터 형식·상태 정의
├─ adapters/
│  ├─ mock_adapter.py             # 시연용 미션 결과 생성
│  └─ ros_adapter.py              # 확정 토픽과 내부 형식 변환
├─ database.py                   # 연결·스키마 버전·초기화
├─ templates/                    # 로그인·대시보드·상세·이력
└─ static/                       # CSS·JS·지도 자산
instance/
├─ sysmon.sqlite3
└─ evidence/                     # 이벤트 근거 이미지
```

실제 구현에서 파일 수는 합칠 수 있지만 routes에 SQL·ROS 수신·업무 규칙을 모두 넣지 않는다. HTTP와 ROS 수신은 동일한 서비스 함수를 호출한다.

## 3. 화면 구성 및 사용자 흐름

| 화면/영역 | 표시 내용 | 사용자 동작 | 연결 서비스 |
| --- | --- | --- | --- |
| 로그인 | 아이디·비밀번호·오류 | 로그인/로그아웃 | auth |
| 통합 대시보드 | 지도, AMR1/2 상태, 영상 4자리, 신규 경고 | 로봇·마커·사건 선택 | robots/maps/cameras/events |
| 지도 | 경로, P1~P7, 로봇·사건·안전구역·도크 | 마커 상세, 지도 버전/층 선택(있는 경우) | maps/robots/events |
| 이벤트 상세 | 근거 이미지, 위치·시각·유형·등급, 메모·변경 이력 | 확인중/작업요청/조치완료 변경 | events |
| 운영 명령 | 대상 로봇, 명령, 요청 ID, 실행 상태·사유 | 요청 생성, 결과 조회 | commands |
| 이력 | 사건/명령/순찰/교대 탭 | 기간·로봇·유형·상태 검색, 상세 | history |
| 사용자 관리 | 계정·역할·활성 상태 | 관리자만 수정 | users/auth |

초기 상태는 지도·관측점 등 정적 데이터만 있고, 로봇은 미수신, 영상은 연결 대기, 사건·명령·순찰·교대 목록은 0건이다. 빈 목록, 검색 결과 없음, 통신 오류, 조회 오류를 각각 구분한다.

지도 좌표는 `map_id`, `frame_id`, `x`, `y`, 필요 시 `yaw`로 받는다. 지도 이미지에 표시하려면 해상도·원점·회전·축 방향을 맞춘다. 좌표 미확정 또는 지도 버전 불일치 이벤트는 목록에 유지하고 지도에 임의로 배치하지 않는다. 안전구역은 면적을 표현하는 polygon, 도크·관측점은 point, 경로는 polyline으로 관리한다.

### 권한 제안

| 동작 | 조회자 | 운영자 | 관리자 |
| --- | --- | --- | --- |
| 지도·영상·상태·이력 조회 | 가능 | 가능 | 가능 |
| 이벤트 메모·처리 변경 | 불가 | 가능 | 가능 |
| 운영 명령 요청 | 불가 | 가능 | 가능 |
| 사용자·권한 관리 | 불가 | 불가 | 가능 |

버튼 표시 여부와 함께 서버에서 권한을 검사한다. 대피 등 명령별 별도 권한은 팀 정책 확정 후 반영한다. 샘플 입력 API는 개발 환경에서만 활성화하고 일반 대시보드 계정과 구분된 입력 인증을 사용한다.

## 4. 데이터 수신·저장·화면 반영

1. 어댑터가 원본 메시지를 공통 내부 형식으로 변환한다.
2. 출처·ID·시각·로봇·지도 참조 및 필드 유효성을 검사한다.
3. `source_id + message_id`로 재전송을 구분한다. 역순 상태가 최신 상태를 덮어쓰지 않도록 소스 순번/시각을 검사한다.
4. 상태는 최신값을 갱신하고 정해진 정책에 따라 이력을 저장한다. 이벤트는 증거와 메타데이터를 저장한다. 명령·순찰·교대 결과는 각각의 ID와 연결한다.
5. 트랜잭션 성공 뒤 UI API 조회 결과에 반영한다. DB 오류는 빈 데이터 성공 응답으로 숨기지 않는다.
6. 새 메시지를 계속 수신한다. 브라우저는 최신 API 결과로 상태·지도·이벤트 목록을 갱신한다.

증거 이미지는 임시 파일 저장 → 정상 파일 확정 → DB 경로 등록 순서로 처리한다. 파일과 SQLite는 하나의 원자적 트랜잭션이 아니므로 DB 실패 시 잔여 파일 정리/재처리 정책이 필요하다. 이미지 누락 시에도 사건 자체를 잃지 않도록 `evidence_status=missing`을 기록하고 화면에 근거 미수신을 표시하는 방안을 제안한다.

영상 원본은 별도 스트림으로 중계한다. 각 영상의 수신 실패를 다른 로봇/카메라 영상과 독립적으로 표시한다.

## 5. 이벤트 업무 흐름

```text
감지 수신 → 검증·중복 확인 → 이벤트/증거 저장 → 신규 경고
→ 사용자 상세 확인 → 확인중 → 작업요청 → 조치완료
```

각 상태 변경은 서버가 `권한 + 현재 상태 + version`을 확인한 뒤, events 갱신과 event_changes 추가를 한 트랜잭션으로 저장한다. 메모만 추가해도 작성자·작성 시각을 남긴다. 상세를 열었다는 이유만으로 자동 확인 처리하지 않는다.

| 현재 상태 | 요청 상태 | 기록 내용 |
| --- | --- | --- |
| 신규 | 확인중 | 확인자·시각·메모 |
| 확인중 | 작업요청 | 요청자·시각·조치 요청 내용 |
| 작업요청 | 조치완료 | 처리자·시각·조치 결과 |

위 전진 경로가 기본이다. 단계 건너뛰기, 오탐·중복 사건 병합, 조치완료 후 재개방은 미결정이다. 상태를 표시하기 위한 문자열을 로봇 임무 상태와 공유하지 않는다.

**작업요청은 시설 사건의 처리 단계다.** 현재 설계에서는 내부 기록이며 자동으로 로봇 명령이나 외부 작업 티켓을 보내지 않는다. 외부 전달을 원하면 수신처·담당자·전달 실패 처리를 별도로 정한다. 위험등급은 감지/판정 모듈이 제공한 값과 판정 근거를 표시하는 것을 기본 제안으로 하며 Sysmon이 임의의 숫자 위험도를 생성하지 않는다.

## 6. 운영 명령 요청·결과 흐름

```text
대상·명령 선택 → 권한/입력 검증 → DB 요청 저장(요청됨)
→ 어댑터 전달 → 미션 모듈 수락 → 진행 → 완료 또는 실패
```

명령 종류: `start_patrol`, `pause`, `resume`, `return_to_dock`, `evacuate` (내부 이름 제안).

명령별 허용 로봇 상태, 안전구역/도크 결정, 경로 유효성, 동시 요청 우선순위, 실제 실행 가능 여부의 최종 판단은 미션 모듈이 담당한다. 웹의 현재 상태는 오래되었을 수 있으므로 버튼 활성화만으로 실행 가능성을 보장하지 않는다.

| 구분 | 값/처리 제안 |
| --- | --- |
| 업무 상태 `status` | 요청됨 → 수락됨 → 진행중 → 완료 / 실패, 수락 전 거절됨 |
| 전송 상태 `delivery_status` | pending / sent / unknown (실행 성공과 구분) |
| 요청 생성 성공 응답 | 202 + request_id + 요청됨; 로봇 수락을 의미하지 않음 |
| 재전송/더블클릭 | 동일 idempotency_key면 같은 request_id 반환; 다른 내용이면 충돌 반환 |
| 응답 지연 | 결과 미확인 표시. 웹 시간 초과만으로 실행 실패 처리하지 않음 |
| 순서가 바뀐 피드백 | 갱신 순번 검증; 완료 이후 이전 진행 메시지가 현재 상태를 되돌리지 않음 |
| 연결 복구 | 동일 요청 ID로 결과 확인/조정; 새 요청 자동 생성하지 않음 |
| 모의 실행 | MockMission 피드백으로 상태 전이, UI에 시연 모드 표시 |

DB 저장 후 전송하므로 서버 재시작 시 미전달 요청을 찾을 수 있다. 전달 후 응답 전 장애는 `unknown`일 수 있다. 외부 미션 모듈도 요청 ID 중복 제거를 지원하는지 확인하기 전에는 무조건 재전송하지 않는다.

명령 상태 이력에는 요청자, 대상, 명령 인자, 외부 결과 시각, 서버 수신 시각, 결과 코드·사유를 남긴다. 성공 UI는 미션 피드백에 근거한다. `start_patrol` 명령 완료가 순찰 전체 완료를 뜻하는지는 미션 계약으로 확정해야 하며, 순찰 완료는 별도 `patrol_id` 결과로 기록한다.

## 7. 순찰·교대 이력

- 순찰은 `patrol_id`, 로봇, 경로 버전, 시작/종료, 진행 상태·결과를 기록한다. 웹 요청과 관계없이 자동 시작된 순찰도 기록 가능해야 한다.
- 관측점 방문은 `patrol_id + observation_point_id + visit_id`와 실제 방문 시각·결과를 기록한다. P1~P7은 기준 관측점이고 재방문은 별개 기록이다.
- 교대는 `handover_id`, 인계 로봇, 인수 로봇, 사유, 시각·결과, 인계 전/후 순찰 ID를 기록한다.
- 교대 발생은 단순 배터리 값 변화로 추측하지 않고 미션 모듈의 기록을 받는다. 교대 알고리즘과 책임 이관 완료 기준은 미결정이다.
- 사건·명령·순찰·교대는 각각 검색하며 관련 ID로 상세 화면을 연결한다.

## 8. DB 스키마 초안

SQLite에서 ID는 TEXT(UUID 등), 시각은 UTC ISO 8601 TEXT, 좌표는 REAL, 역할·상태는 TEXT와 CHECK 또는 서버 검증을 사용한다. FK를 활성화하고 입력 검증과 DB 제약을 함께 사용한다. 화면에서 KST로 변환한다. 아래는 논리 스키마이며 SQL 구현은 다음 단계다.

| 테이블 | 주요 열 및 제약 |
| --- | --- |
| users | user_id PK, username UNIQUE, password_hash, role, is_active, created_at |
| robots | robot_id PK, name, model, is_active |
| robot_latest_status | robot_id PK/FK, battery_pct, mission_state, map_id, frame_id, x/y/yaw, observed_at, received_at, sequence; 미수신 값은 NULL |
| robot_status_history | id PK, robot_id FK, 상태 스냅샷, observed_at/received_at, source_id/message_id UNIQUE |
| maps | map_id PK, version, image_path, resolution, origin, rotation, floor, frame_id |
| map_features | feature_id PK, map_id FK, kind(point/safe_zone/dock), geometry_json, label; 관측점 7개 seed |
| routes | route_id PK, map_id FK, version, ordered_point_ids, geometry_json |
| cameras | camera_id PK, robot_id FK NULL, name, source_type, source_ref; 연결 정보는 환경 설정에서 관리 |
| events | event_id PK, source_id/source_event_id UNIQUE, robot_id FK NULL, camera_id FK NULL, patrol_id FK NULL, type, severity, measurement_json, map_id, frame_id, x/y, location_valid, detected_at/received_at, status, version |
| event_evidence | evidence_id PK, event_id FK, image_path, captured_at, evidence_status |
| event_changes | change_id PK, event_id FK, actor_id FK, action_type, from_status/to_status, memo, created_at |
| commands | request_id PK, idempotency_key UNIQUE(요청자 범위), robot_id FK, requested_by FK, type, params_json, status, delivery_status, created_at, last_feedback_at |
| command_updates | update_id PK, request_id FK, external_update_id UNIQUE(소스 범위), status, reason_code/text, sequence, occurred_at/received_at |
| patrol_runs | patrol_id PK, robot_id FK, route_id/version, request_id FK NULL, status, started_at/ended_at, result |
| patrol_visits | visit_id PK, patrol_id FK, point_id FK, visited_at, result, source_message_id UNIQUE(소스 범위) |
| handovers | handover_id PK, from_robot_id/to_robot_id FK, previous_patrol_id/next_patrol_id FK NULL, status, reason, requested_at/completed_at |
| handover_updates | update_id PK, handover_id FK, status, occurred_at/received_at, source_message_id UNIQUE(소스 범위) |

지도·경로는 시제품에서 JSON으로 시작할 수 있다. 상태 이력은 모든 영상 프레임마다 저장하지 않으며 상태 변화/주기 저장 기준을 정한다. 조회용 인덱스는 사건 `(detected_at, robot_id, status)`, 명령 `(created_at, robot_id, status)`, 순찰·교대 시각/로봇을 우선한다. 실제 쿼리와 데이터 규모로 최종 조정한다.

연결 정상/단절은 `received_at` 기준 파생 상태로 표시한다. `mission_state=순찰`과 `connection=단절`은 동시에 가능하다. UI에 마지막 확인된 상태라고 명시한다.

## 9. 임시 API 계약 제안

| 메서드·경로 | 역할 |
| --- | --- |
| POST /api/auth/login, /logout | 로그인/로그아웃 |
| GET /api/me | 현재 사용자·권한 |

| GET /api/maps/{id} | 지도·경로·7관측점·영역·도크 |
| GET /api/cameras, /api/cameras/{id}/stream | 영상 소스 상태·스트림 |
| GET /api/events, /api/events/{id} | 필터·페이지 기반 목록/상세 |
| PATCH /api/events/{id}/status | target_status, expected_version, memo |
| POST /api/events/{id}/notes | 사건 메모 추가 |
| POST /api/commands | robot_id, type, params, idempotency_key |
| GET /api/commands, /api/commands/{id} | 요청 목록·현재 상태·변경 이력 |
| GET /api/history/events, /commands, /patrols, /handovers | 기간·로봇·상태 필터와 페이지 조회 |
| POST /dev/ingest/status, /events | 개발용 모의 로봇 상태·이벤트 수신 |
| POST /dev/ingest/command-updates | 모의 미션 수락·진행·결과 |
| POST /dev/ingest/patrols, /visits, /handovers | 모의 순찰·방문·교대 기록 |

조회 응답은 `items`, `total`, `page`, `updated_at`를 기본 제안으로 한다. 잘못된 입력은 400, 미인증 401, 무권한 403, 상태/버전 충돌 409로 구분한다. 증거 이미지는 파일시스템 경로를 직접 노출하는 대신 인증된 미디어 URL로 제공한다.

### 공통 입력 예시 (토픽 미정과 무관한 내부 계약)

```json
{
  "source_id": "mock-detector",
  "message_id": "msg-001",
  "source_event_id": "evt-001",
  "robot_id": "AMR1",
  "type": "water_leak_candidate",
  "detected_at": "2026-09-06T05:32:00Z",
  "map_id": "parking-demo-v1",
  "frame_id": "map",
  "position": {"x": 12.4, "y": 8.1},
  "location_valid": true,
  "severity": "warning",
  "measurements": {},
  "evidence_ref": "sample-leak-001"
}
```

종류 이름과 등급 문자열은 임시 계약이다. `evidence_ref`는 이미 업로드한 증거 자산 ID로 해석하고 임의 서버 파일 경로로 취급하지 않는다. 실제 ROS 메시지에 필드가 빠져 있으면 어댑터에서 유효성/미수신 여부를 명시한다.

## 11. 완료 확인과 시연 시나리오

| 검증 | 입력/행동 | 확인 결과 |
| --- | --- | --- |
| 로그인·권한 | 틀린 비밀번호 / 조회자 명령 요청 | 오류/403, 데이터 변경 없음 |
| 빈 상태 | 계정·지도만 있는 시연 DB | 7관측점 표시, 로봇 미수신·영상 대기·이력 0건 |
| 로봇별 갱신 | AMR1/2 서로 다른 상태·배터리 입력 | 다른 로봇 값과 섞이지 않음 |
| 지도·영상 | 유효/무효 좌표와 영상 단절 | 유효 마커 표시, 좌표 불명 안내, 해당 영상만 단절 표시 |
| 사건 저장 | 누수 의심 + 이미지 입력 | DB 1건, 지도/목록/근거 표시 |
| 사건 처리 | 신규→확인중→작업요청→조치완료, 메모 | 상태와 변경자·시각·메모 이력 보존 |
| 충돌 | 같은 사건에 오래된 version으로 변경 | 409, 기존 이력 보존 |
| 명령 정상 | 순찰 시작 요청 + 모의 수락/진행/완료 | 동일 request_id로 상태 갱신 |
| 명령 예외 | 거절/실패/응답 지연, 더블클릭 | 사유 구분, 지연≠실행 실패, 중복 명령 없음 |
| 순찰·교대 | 방문 P1~P7, AMR1→AMR2 교대 기록 | 사건·명령 이력과 구분하여 검색 가능 |
| 지속성 | 로그아웃 중 사건 입력, 서버/화면 재접속 | 저장 이력 유지, 최신 시각·연결 상태 재평가 |
| 검색 | 기간·로봇·유형·상태 조건 및 결과 0건 | 정확한 목록·상세 또는 결과 없음 |

영상은 모의 데이터 구간과 실제 로봇 구간을 명확히 표시한다. 화면 목업만 움직인 것은 DB·명령 동작 검증으로 사용하지 않는다.
